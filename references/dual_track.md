# 双轨输出：客户版（A 轨） vs 销售版（B 轨）分离规范

> 核心诉求：**给客户的对外资料保持纯净专业；销售自己的话术/讲稿单独成文，绝不混进客户 PPT。**
> 两种轨共用同一 config 数据源，但字段不同，天然避免「话术泄露给客户」。

---

## 一、为什么拆双轨

- **客户版**要的是「结果导向、干净、可交付」——客户看重的是方案的专业度与数据说服力，不是销售怎么开口。
- **销售版**要的是「怎么开口、客户问什么怎么答、哪些数据能引」——销售看重的是成交推进。
- 把「现场话术」写进客户 PPT，会让客户觉得方案「不成熟、像推销」，拉低专业感。

---

## 二、两轨的交付物清单

### A 轨 · 客户可见（对外交付）

| # | 文件 | 生成器 | 含话术？ |
|---|---|---|---|
| 1 | `<品牌>_微盟星启GEO优化方案.pptx`（20 页） | `scripts/build_deck.py` | **不含** |
| 2 | `<品牌>_国内版GEO话题词方案.html` | `scripts/build_topic.py` | 含「现场话术」字段（与用户已确认的 Phase A HTML 一致） |

> **核心保证**：客户版 **PPT** 第 18 页只放「话题词 + 平台双版本 + KPI」，绝不出现现场话术。
> 话题词方案 HTML 的「现场话术」区块保留——它是销售逐题打法，且与销售 talktrack 的逐题话术同源；
> 若某客户要求 HTML 也纯净，可将 `topic_config.py` 的 `TOPICS[].script_v` 置空后再 `build_topic.py`（`script_v` 为空则该卡不输出话术块）。

### B 轨 · 销售内部（不对外）

| # | 文件 | 生成器 | 内容 |
|---|---|---|---|
| 1 | `<品牌>_销售话术讲稿.md` | `scripts/build_talktrack.py` | 开场/报价/异议/收尾话术 + 20 页逐页讲稿 + 可引用硬数据清单 + 合规红线 |

> B 轨文件默认输出到 `cases/<name>/output/`，与客户版同目录但为独立 `.md`，不进入客户 PPT。

---

## 三、数据源与字段隔离

同一个案例，PPT 数据在 `cases/<name>/config.py`，话题词数据在 `cases/<name>/topic_config.py`。
talktrack 同时读两者，但**只取销售需要的字段**：

| 字段 | 客户版（A 轨） | 销售版（B 轨） |
|---|---|---|
| AIVO 总分 / 被引用率 / 竞品排名 | ✓ 展示 | ✓ 引用为「硬数据」 |
| 现场话术 `script_v` | ✗ 隐藏 | ✓ 输出 |
| 异议处理话术 | ✗ 不生成 | ✓ 输出 |
| 合规红线（forbidden/allowed） | ✓ 以声明形式展示 | ✓ 以销售口径提示 |
| 联系方式 | ✓ 结尾页 | ✓ 收尾号召 |

> 铁律：**客户版 PPT 与 HTML 中绝不出现 `script_v`（现场话术）与异议处理台词。**

---

## 四、实施要点（在引擎中的体现）

1. `deck_engine.py` / `topic_engine.py` 不读 `script_v`，只读数据字段——保证客户版天然纯净。
2. `talktrack.py` 才读 `script_v` 与销售话术——保证话术只在内部文档。
3. 若某个 case 暂时没有 `topic_config.py`，talktrack 自动跳过「话题词逐题话术」一节，不报错。

---

## 五、QA 核验（双轨纯净性）

- 客户版 PPT 全文字符串里**不出现** `script_v` 的文本（可在 qa 时抽验）。
- 客户版 HTML 的「现场话术」区块计数为 0。
- 销售版 `.md` 须包含「内部资料，仅限销售使用」字样。
