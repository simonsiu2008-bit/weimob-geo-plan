# 線上數據實查 + 痛點問答證據卡

> **解決的根因**：現場診斷報告「內容太簡單」，是因為過去直接用模擬數填充、冇做線上數據收集。
> 本規範把「先實查、後估算」定為硬性前置——有證據先寫方案，冇證據唔准扮有。

---

## 一、實查清單（Step 1.5，WebSearch / WebFetch 執行）

| # | 實查對象 | 查咩 | 產出去向 |
|---|---|---|---|
| 1 | 品牌官網 | 可抓性、結構化數據、內容新鮮度 | 第 11 頁品牌基建診斷 |
| 2 | 權威平臺收錄 | 百科 / 新聞 / 百家號 / 知乎 / 行業媒體有幾多條、幾新 | 第 8 頁信源清單、第 9 頁引用偏好 |
| 3 | 社媒聲量 | 官方帳號活躍度、內容量、互動 | 第 11 頁 |
| 4 | 負面信息 | 負面評測 / 投訴 / 過時信息（價格停更、門店錯誤等） | 第 12 頁輿情 + 證據卡 `wrong`/`negative` |
| 5 | 競品佈局 | 競品喺內容平臺嘅覆蓋、被 AI 引用嘅痕跡 | 第 14/15 頁競品基準 + 證據卡 `absent` |
| 6 | AI 平臺問答 | 有工具就實測；冇工具就**模擬問答還原**（見第三節） | 第 5/7 頁 + 證據卡 |

**規則**：實查結果直接餵入 PPT 對應頁嘅數據卡——A/B 級證據優先，C 級估算只補實查唔到嘅缺口。
報告嘅厚度由證據量決定，唔係由模板決定。

---

## 二、證據分級標註（硬性）

| 級別 | 標註文案 | 要求 |
|---|---|---|
| **A 線上實查** | `線上實查（YYYY-MM-DD，來源：xxx）` | 帶日期＋來源名，可回溯 |
| **B 客戶提供** | `客戶提供（YYYY-MM-DD）` | 截圖 / 後台數據，註明提供日期 |
| **C 診斷模型估算** | `微盟星启 GEO 診斷模型估算（口徑）` | 現有紀律不變，只補缺口 |

- 實查與估算**不得混標**：唔可以把 C 級數寫成實查，唔可以只寫「實查」冇日期冇來源。
- 與既有紀律銜接：估算仍一律標「診斷模型估算」，禁用 `虛擬 / ⚠️ / website / {{`。

---

## 三、模擬問答還原（AI 平臺問答嘅呈現方式）

AI 平臺內部問答多數無法直接 API 實測，允許**模擬還原**，但必須：

1. 問題來自真實監測池 / 客戶客群高頻問法（唔好編離譜問題）；
2. 回答內容基於 A 級實查事實 + 競品公開佈局還原，唔好憑空捏造細節；
3. 頁眉聲明「**示意問答還原**」，每卡帶 A/B/C 級別，讓客戶知道證據成色。

## 四、三類痛點卡（`build_evidence.py`）

| kind | 場景 | 客戶視角（白話） |
|---|---|---|
| `absent` | **對手出現、本品牌冇出現** | 「客戶問緊我嘅品類，AI 推嘅全係競品——我連入場資格都冇」 |
| `negative` | **本品牌被負面提及** | 「AI 講到我就好，但講嘅係負面評測——等於幫對手做廣告」 |
| `wrong` | **信息錯誤 / 過時** | 「AI 講嘅價格/門店/產品係舊嘅——客戶未見面已經被我錯誤信息勸退」 |

### `cases/<name>/evidence_config.py` 字段

```python
EVIDENCE_CONFIG = {
    "OUT_FILENAME":  "<品牌>_<版本>GEO問答證據卡.html",
    "BRAND_CN":      "品牌名",
    "VERSION_SCOPE": "国内版",          # 與 config.py 一致
    "SOURCE_NOTE":   "示意問答還原 · 2026-XX 線上實查 + 診斷模型估算",
    "PALETTE_HEX":   { 11 個邏輯色名 → hex },   # 與 config.py 的 PALETTE 同源
    "FONT":          "微軟雅黑",
    "CARDS": [
        {
            "kind": "absent",             # absent / negative / wrong
            "level": "A",                 # A 線上實查 / B 客戶提供 / C 診斷模型估算
            "platform": "豆包",
            "question": "客戶會咁問……",
            "answer":  "AI 回答還原……（含競品名）",
            "mentions": ["競品A", "競品B"],  # 要高亮的非品牌實體
            "pain":   "白話痛點一句話",
            "action": "建議下一步一句話",
        },
    ],
}
```

生成：`python3 scripts/build_evidence.py cases/<name>` → `cases/<name>/output/`。

---

## 五、QA 要點

- 每卡必帶 `level`；頁眉有「示意問答還原」聲明。
- 痛點（`pain`）與建議（`action`）必須過 `plain_language.md` 白話自查——證據卡係畀老闆睇嘅，唔係畀 SEO 同行睇嘅。
- `VERSION_SCOPE` 與證據卡 badge 一致；卡內平臺只准出現範圍內平臺。
- 禁忌標記為 0（引擎內建校驗，命中即報錯）。
