# 三阶段工作流：报价前 → 报价 → 报价后最终版

> 目标：把「拿到正式报价后才生成最终版」的销售节奏固化为可复用流程，对客户更具体、对销售更清晰。

---

## 一、为什么是「报价后最终版」

- **报价前**：客户对自身位置与市场机会还没有概念，直接给详细方案会「剧透」且难促成报价。
- **报价后**：客户已认可服务价值并拿到报价表，此时给「基于报价表话题词的具体方案」最有效——既证明专业，又推动成交。

三个版本分别对应不同销售阶段，**不是三个并列方案，而是递进交付**。

---

## 二、三阶段总览

| 阶段 | 触发时机 | 交付物 | 侧重点 | 对应 case 数据 |
|---|---|---|---|---|
| **Stage 1 · 诊断数据** | 售前沟通 | 诊断简报（AIVO / 曝光 / 舆情 / 竞品基线） | 让客户看清「现在排第几、差距在哪」 | `config.py` 的诊断数据 |
| **Stage 2 · 话题词方案** | 意向确认 | 话题词方案 HTML + 销售 talktrack | 让销售有话题打法、客户有方向 | `topic_config.py` |
| **Stage 3 · 报价后最终版** | **拿到正式报价** | 20 页客户版 PPT + PDF + talktrack | 对客户具体、对销售清晰、可签约 | 综合两轨 + 报价表话题词 |

> Stage 3 的「报价表话题词」是硬约束：**话题词必须与报价表一字不差**，不得自行增删（尤其受监管品类）。

---

## 三、每阶段的动作清单

### Stage 1 · 诊断数据（售前）
1. 采集国内 6 平台 × 15~20 问的模拟收录。
2. 算出 AIVO 四维、被引用率、曝光缺口、舆情健康度、竞品基线。
3. 产出诊断简报，让客户对「排名锚点 / 可见度双指标」有直观认知。
4. **不提前给具体话题词打法**，保留成交钩子。

### Stage 2 · 话题词方案（意向确认后）
1. 用 `topic_framework.md` 定 L1/L2/L3 三层话题。
2. 建 20 题监测池（零品牌名，纯品类/场景词）。
3. 生成话题词方案 HTML（含合规红线 + 内容处方 + 投放优先级）。
4. 生成销售 talktrack（含逐题话术、异议处理）。

### Stage 3 · 报价后最终版（拿到报价表后）
1. **以报价表话题词为准**，把 HTML/PPT 的话题词与其对齐（一字不差）。
2. 生成 20 页客户版 PPT（纯净、不含话术）。
3. 渲染 PDF 备份；生成最终 talktrack。
4. 交付前跑 `qa_check.py`：页数 20、OOB 0、禁忌词 0、**话题词与报价表一致**、跨 case 污染 0。

---

## 四、三阶段在 case 目录中的体现

```
cases/<name>/
├── config.py          # Stage 1 诊断数据 + Stage 3 PPT（AIVO/曝光/竞品/KPI/话题词）
├── topic_config.py    # Stage 2 话题词方案（L1/L2/L3 + 20 题池 + 话术）
├── pollute_words.txt  # 本案例行业词（供跨 case 反查）
└── output/            # 全部阶段输出隔离在此
```

- 三阶段共用**同一份 config / topic_config**，只是按阶段「生成哪些交付物」不同。
- 数据一经 stage 1 确定，stage 2/3 复用，避免重复采集与口径漂移。

---

## 五、QA 核验（三阶段一致性）

- **话题词一致性（硬性）**：Stage 3 客户版 PPT 第 18 页 `TOPIC_WORDS` ↔ 话题词方案 HTML `TOPICS` ↔ 报价表话题词，三处一字不差。
- **诊断口径一致**：各阶段「诊断模型估算」口径串相同。
- **合规**：受监管品类各阶段内容均只做成分/正品/品质/选购，不作功效声称。
